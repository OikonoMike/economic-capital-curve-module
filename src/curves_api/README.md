# Curves API

## 1. Назначение

Curves API — серверная часть модуля кривых процентных ставок. Сервис предоставляет HTTP API для получения рассчитанных базовой и стрессовых кривых, экспорта результатов и просмотра истории запусков калькулятора.

**Технологии:**
- Python 3.12+
- FastAPI
- SQLAlchemy
- PostgreSQL
- psycopg
- openpyxl

API подключается к PostgreSQL под пользователем `calc_ro` с правами только на чтение.

## 2. Запуск сервиса

Перейти в корневую папку проекта и активировать виртуальное окружение:

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Настроить переменные окружения в `.env` (см. раздел 3).

Запустить сервер:

```bash
uvicorn src.curves_api.main:app --reload
```

API доступен по адресу: `http://127.0.0.1:8000`.

Интерактивная документация Swagger: `http://127.0.0.1:8000/docs`.

## 3. Настройка подключения к базе данных

Настройки подключения API задаются через переменные окружения:

| Переменная | Назначение |
|---|---|
| API_DB_HOST | Адрес PostgreSQL |
| API_DB_PORT | Порт PostgreSQL |
| API_DB_NAME | Имя базы данных |
| API_DB_USER | Пользователь базы данных |
| API_DB_PASSWORD | Пароль пользователя |

Пример настроек в `.env`:

```env
API_DB_HOST=localhost
API_DB_PORT=5433
API_DB_NAME=irrbb
API_DB_USER=calc_ro
API_DB_PASSWORD=your_password
```

Порт должен соответствовать настройке публикации PostgreSQL в Docker Compose.

Пароль API должен соответствовать паролю роли `calc_ro`, заданному при инициализации базы данных (`CALC_PASSWORD`).

Файл `.env` не должен попадать в Git. Для примера настроек используется `.env.example`.

## 4. Методы API

### 4.1. Получение кривых

**GET /curves**

Получение рассчитанных кривых на указанную отчётную дату.

Параметры:

| Параметр | Обязательный | Описание |
|---|---|---|
| date | Да | Отчётная дата в формате YYYY-MM-DD |
| scenario | Нет | Идентификатор сценария от 0 до 6 |

Пример:

```http
GET /curves?date=2026-10-30
```

Получение только базового сценария:

```http
GET /curves?date=2026-10-30&scenario=0
```

Данные выбираются из представления `curve_latest` с соединением с таблицей `curve_run` по `run_id`.

Возвращаемые поля:

| Поле | Описание |
|---|---|
| report_date | Отчётная дата |
| scenario_id | Идентификатор сценария |
| scenario_code | Код сценария |
| tenor_label | Название тенора |
| tenor_years | Значение тенора в годах |
| t_mid_years | Время до середины интервала |
| rate_pct | Процентная ставка |
| discount_factor | Дисконтирующий коэффициент |
| method | Метод получения ставки |
| is_interpolated | Признак интерполяции |
| is_extrapolated | Признак экстраполяции |
| calculated_at | Время построения кривой |
| run_type | Тип запуска расчёта |
| started_by | Инициатор запуска |
| started_at | Время начала запуска |

Результат сортируется по `scenario_id`, затем по `order_no`.

Без параметра `scenario` возвращаются все доступные сценарии выбранного запуска.

### 4.2. Экспорт кривых

**GET /curves/export**

Экспорт рассчитанных кривых в CSV или XLSX.

Параметры:

| Параметр | Обязательный | Описание |
|---|---|---|
| date | Да | Отчётная дата в формате YYYY-MM-DD |
| format | Да | Формат файла: csv или xlsx |
| scenario | Нет | Идентификатор сценария от 0 до 6 |

Примеры:

```http
GET /curves/export?date=2026-10-30&format=csv
```

```http
GET /curves/export?date=2026-10-30&format=xlsx
```

Экспорт без фильтра сценария содержит базовую и стрессовые кривые выбранного запуска.

При указании `scenario` экспортируется только соответствующий сценарий.

Файл формируется с теми же полями, что и ответ `/curves`.

### 4.3. История запусков

**GET /runs**

Возвращает историю запусков калькулятора из таблицы `curve_run`.

Пример:

```http
GET /runs
```

Возвращаемые поля:

| Поле | Описание |
|---|---|
| run_id | Идентификатор запуска |
| report_date | Отчётная дата |
| run_type | Тип запуска (manual / scheduled) |
| status | Статус выполнения |
| started_at | Время начала |
| finished_at | Время завершения |
| started_by | Инициатор запуска |
| error_message | Сообщение об ошибке |

Запуски сортируются по времени начала в обратном хронологическом порядке.

## 5. Обработка ошибок

| HTTP-код | Описание |
|---|---|
| 200 | Запрос выполнен успешно |
| 400 | Некорректный формат или значение даты |
| 404 | Кривые за указанную дату не найдены |
| 422 | Ошибка валидации параметров запроса |
| 500 | Внутренняя ошибка сервера |

Примеры:

Некорректная дата:

```http
GET /curves?date=30-10-2026
```

Ответ: `400 Bad Request`.

Отсутствие данных:

```http
GET /curves?date=2020-01-01
```

Ответ: `404 Not Found`.

## 6. Тестирование

Запуск тестов API:

```bash
python -m pytest -v tests/test_curves_api.py
```

Запуск полного набора тестов проекта:

```bash
python -m pytest -v
```

API-тесты используют подмену подключения к базе данных и не требуют работающего PostgreSQL.

Проверяются:
- успешное получение кривых;
- обработка некорректной даты;
- обработка отсутствующих данных.

## 7. Структура модуля

```text
src/curves_api/
├── main.py
├── database.py
├── schemas.py
├── routers/
│   ├── __init__.py
│   ├── curves.py
│   └── runs.py
└── README.md
```

- `main.py` — создание FastAPI-приложения и подключение маршрутов.
- `database.py` — подключение к PostgreSQL.
- `schemas.py` — схемы ответов API.
- `routers/curves.py` — получение и экспорт кривых.
- `routers/runs.py` — история запусков.
