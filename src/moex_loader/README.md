# MOEX Loader

## 1. Описание проекта

MOEX Loader — модуль получения исходных данных Московской биржи (MOEX) для построения бескупонной кривой доходности и сохранения результатов в PostgreSQL.

Модуль входит в проект **«Эконом Капитал. Модуль кривых»** и является первым этапом единого pipeline обработки данных.

Pipeline выполняет два последовательных этапа:

1. Получает и проверяет исходные рыночные данные MOEX.
2. При успешной загрузке рассчитывает кривые и сохраняет результаты в PostgreSQL.

Оба этапа выполняются в рамках одного запуска и используют общий `run_id`. Если загрузка завершается ошибкой или данные отсутствуют, расчёт кривых не запускается.

Основные задачи модуля:

- получение данных MOEX через API;
- проверка полученных значений;
- проверка торговых дат по производственному календарю;
- сохранение информации о запусках;
- запись исходных рыночных данных в PostgreSQL;
- расчёт кривых на основе загруженных данных;
- сохранение рассчитанных значений;
- обработка ошибок и фиксация статуса выполнения.

## 2. Архитектура и последовательность выполнения

Основная точка входа проекта — `main.py`.

Общая последовательность работы:

1. Пользователь или планировщик запускает `main.py`, передавая дату и режим выполнения.
2. Pipeline проверяет дату по производственному календарю.
3. Создаётся запись запуска в `curve_run`.
4. MOEX Loader получает данные от биржи и выполняет проверки.
5. При успешной загрузке исходные данные сохраняются в `moex_raw`.
6. Pipeline получает данные из `moex_raw` по текущему `run_id`.
7. Модуль интерполяции рассчитывает кривые.
8. Рассчитанные значения сохраняются в `curve_point`.
9. В `curve_run` фиксируется итоговый статус выполнения.

Для загрузки и расчёта используется один `run_id`. Это позволяет связать исходные данные, результаты расчёта и информацию о запуске.

Если дата является нерабочей, загрузка не выполняется. Если MOEX не вернула данные или загрузка завершилась ошибкой, расчёт также не запускается.

## 3. Функциональность загрузчика

### 3.1. Получение данных MOEX

Модуль `moex_client.py` отвечает за взаимодействие с API Московской биржи (MOEX ISS).

Полученные данные содержат сроки до погашения и соответствующие им ставки доходности.

При временных ошибках запроса загрузчик поддерживает повторные попытки. Количество попыток, пауза между ними и тайм-аут настраиваются параметрами запуска.

### 3.2. Проверка торговых дат

Перед загрузкой выполняется проверка даты по таблице производственного календаря `calendar`.

Календарь содержит следующие поля:

- `calendar_date` — календарная дата;
- `is_working_day` — признак рабочего дня;
- `is_trading_day` — признак торгового дня;
- `note` — дополнительная информация.

Если дата не является торговой, pipeline пропускает загрузку и фиксирует соответствующий статус запуска.

### 3.3. Проверка полученных данных

После получения ответа MOEX выполняются проверки качества данных.

Результаты проверок сохраняются в таблице `data_check` и связываются с текущим `run_id`.

Если проверки не пройдены, загрузка считается неуспешной, а расчёт кривых не запускается.

### 3.4. Управление запусками

Каждый запуск pipeline регистрируется в таблице `curve_run`.

Для запуска сохраняются:

- дата отчёта;
- тип запуска;
- время начала и завершения;
- статус выполнения;
- сообщение об ошибке;
- инициатор запуска.

Возможные итоговые статусы:

| Статус | Значение |
|---|---|
| `success` | Загрузка и расчёт кривых завершились успешно |
| `error` | При загрузке или расчёте возникла ошибка |
| `no_data` | Данные MOEX отсутствуют |
| `skipped` | Запуск пропущен, например из-за нерабочего дня или уже выполненного успешного запуска |

### 3.5. Сохранение исходных данных

Результаты загрузки сохраняются в таблице `moex_raw`.

Для предотвращения повторной записи одинаковых наблюдений в рамках одного запуска используется уникальность пары:

`(run_id, tenor_years)`

Исходные данные связываются с записью запуска через `run_id`.

## 4. Расчёт кривых

После успешной загрузки pipeline передаёт исходные наблюдения в модуль `src/interpolate_curve.py`.

Расчёт выполняется функцией `calculate_curves()`, которая формирует кривые на основе полученных от MOEX сроков и ставок.

Функция `to_long_format()` преобразует результат расчёта в формат для сохранения в базе данных.

Рассчитанные значения записываются в таблицу `curve_point`.

В таблице хранятся:

- идентификатор запуска `run_id`;
- сценарий `scenario_id`;
- срок `tenor_label`;
- срок в годах `tenor_years`;
- середина интервала `t_mid_years`;
- ставка `rate_pct`;
- коэффициент дисконтирования `discount_factor`;
- метод расчёта `method`;
- признаки интерполяции и экстраполяции;
- время расчёта `calculated_at`.

Результаты расчёта связаны с исходными данными через общий `run_id`.

## 7. Структура данных

Pipeline использует общую схему базы данных проекта.

Основные таблицы:

- `curve_run` — информация о запусках;
- `moex_raw` — исходные данные MOEX;
- `data_check` — результаты проверок исходных данных;
- `calendar` — производственный календарь;
- `scenario` — справочник сценариев;
- `tenor_grid` — сетка сроков;
- `curve_point` — рассчитанные значения кривых.

### 7.1. Таблица `curve_run`

Хранит информацию о каждом запуске pipeline.

`run_id` используется для связи запуска с исходными данными и рассчитанными значениями.

### 7.2. Таблица `moex_raw`

Содержит исходные данные бескупонной кривой доходности, полученные от MOEX.

Основные поля:

| Поле | Назначение |
|---|---|
| `raw_id` | Идентификатор записи |
| `run_id` | Идентификатор запуска |
| `tenor_years` | Срок до погашения в годах |
| `rate_pct` | Ставка доходности в процентах |
| `moex_tradetime` | Время торгового наблюдения |
| `loaded_at` | Время загрузки записи |

Уникальность `(run_id, tenor_years)` ограничивает повторную запись одного срока в рамках одного запуска.

### 7.3. Таблица `curve_point`

Содержит рассчитанные значения кривых.

Результаты сохраняются с привязкой к `run_id` и сценарию. Для одной комбинации запуска, сценария и срока предусмотрена уникальность:

`(run_id, scenario_id, tenor_label)`

Поле `calculated_at` фиксирует время расчёта.

### 7.4. Таблица `calendar`

Содержит календарные признаки, используемые для проверки допустимости даты запуска.

Таблицы создаются средствами инфраструктуры проекта и не должны создаваться загрузчиком самостоятельно.

## 8. Настройка окружения

### 8.1. Создание виртуального окружения

Из корня репозитория выполните:

```bash
python -m venv .venv
source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

### 8.3. Настройка переменных окружения

Создайте локальный файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Настройте параметры подключения к PostgreSQL в соответствии с конфигурацией вашей среды.

Если используется `DATABASE_URL`, укажите строку подключения к базе данных. В противном случае подключение формируется из отдельных параметров окружения, предусмотренных конфигурацией проекта.

Не добавляйте реальные пароли и другие секреты в Git. Файл `.env` должен оставаться локальным.

## 9. Запуск pipeline

Запуск выполняется из корня репозитория при активированном виртуальном окружении.

### 9.1. Запуск за одну дату

```bash
python main.py --date 2026-10-30 --mode manual
```

Параметры:

- `--date` — дата, за которую выполняется pipeline;
- `--mode` — режим запуска: `manual` или `scheduled`.

### 9.2. Запуск за диапазон дат

```bash
python main.py --from-date 2026-10-01 --to-date 2026-10-30 --mode manual
```

Pipeline последовательно обрабатывает каждую дату указанного диапазона.

### 9.3. Дополнительные параметры

При необходимости можно настроить параметры запросов к MOEX:

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `--retries` | Количество повторных попыток запроса | `3` |
| `--retry-pause` | Пауза между повторными попытками, секунды | `2` |
| `--request-pause` | Пауза между датами при обработке диапазона, секунды | `1` |
| `--timeout` | Тайм-аут запроса, секунды | `20` |

Пример:

```bash
python main.py --date 2026-10-30 --mode manual --retries 3 --timeout 20
```

Для просмотра всех доступных параметров:

```bash
python main.py --help
```

## 13. Обработка ошибок

Ошибки загрузки и расчёта фиксируются в таблице `curve_run`.

В поле `status` сохраняется итоговый статус выполнения, а в `error_message` — описание возникшей ошибки.

Если загрузка завершилась неуспешно:

- исходные данные не передаются на расчёт;
- расчёт кривых не выполняется;
- итоговый статус и сообщение об ошибке сохраняются в `curve_run`.

Если загрузка успешна, но ошибка возникает на этапе расчёта, pipeline фиксирует ошибку расчёта в той же записи запуска.

Это позволяет отслеживать весь процесс обработки данных по единому `run_id`.

## 14. Ограничения и особенности

- Pipeline использует общую схему базы данных проекта.
- Структура таблиц должна быть подготовлена до запуска.
- Загрузка и расчёт выполняются в рамках одного `run_id`.
- При отсутствии данных или ошибке загрузки расчёт не запускается.
- Дата отчёта хранится в `curve_run.report_date`.
- Исходные данные и результаты расчёта связываются через `run_id`.
- Повторный успешный запуск за ту же дату пропускается.
- Доступность данных зависит от API MOEX и корректности подключения к PostgreSQL.

## 15. Результат работы

В результате успешного выполнения pipeline:

1. Исходные данные MOEX сохраняются в `moex_raw`.
2. Результаты проверок сохраняются в `data_check`.
3. Рассчитанные значения кривых сохраняются в `curve_point`.
4. В `curve_run` фиксируется успешный статус выполнения.

Таким образом, единый pipeline обеспечивает полный цикл обработки данных: от получения рыночных наблюдений MOEX до сохранения рассчитанных кривых доходности в PostgreSQL.
