# MOEX Loader

## 1. Описание проекта

MOEX Loader — модуль загрузки данных Московской биржи (MOEX), предназначенный для получения ставок бескупонной кривой доходности и сохранения результатов в PostgreSQL.

Модуль входит в проект **«Эконом Капитал. Модуль кривых»** и обеспечивает получение исходных рыночных данных для последующих этапов обработки и построения кривой.

Основные задачи модуля:

- получение данных MOEX через API;
- обработка и проверка полученных значений;
- проверка торговых дат по производственному календарю;
- сохранение информации о запусках загрузчика;
- запись исходных рыночных данных в PostgreSQL;
- обработка ошибок загрузки и фиксация статуса выполнения;
- поддержка запуска с указанием инициатора.

## 2. Функциональность

### 2.1. Получение данных MOEX

Модуль `moex_client.py` отвечает за взаимодействие с источником данных MOEX.

Полученные данные используются для формирования набора наблюдений, содержащих сроки до погашения и соответствующие им ставки.

### 2.2. Проверка торговых дат

Перед загрузкой выполняется проверка даты по таблице производственного календаря `calendar`.

Календарь содержит следующие поля:

- `calendar_date` — календарная дата;
- `is_working_day` — признак рабочего дня;
- `is_trading_day` — признак торгового дня;
- `note` — дополнительная информация.

Проверка позволяет учитывать торговый календарь при выполнении загрузки.

### 2.3. Управление запусками

Каждый запуск загрузчика регистрируется в таблице `curve_run`.

Для запуска сохраняются дата отчёта, тип запуска, время начала и завершения, статус выполнения, сообщение об ошибке и инициатор запуска.

Это позволяет отслеживать результаты выполнения загрузчика и связывать полученные рыночные данные с конкретным запуском.

### 2.4. Сохранение исходных данных

Результаты загрузки сохраняются в таблице `moex_raw`.

Для предотвращения повторной записи одинаковых наблюдений в рамках одного запуска используется уникальность пары:

`(run_id, tenor_years)`

В случае ошибки информация о выполнении сохраняется в записи запуска.

## 5. Структура данных

Загрузчик использует три таблицы общей схемы проекта: `curve_run`, `moex_raw` и `calendar`.

### 5.1. Таблица `curve_run`

Таблица хранит информацию о запусках загрузчика.

| Поле | Назначение |
|---|---|
| `run_id` | Идентификатор запуска |
| `report_date` | Дата отчёта, для которой выполняется загрузка |
| `run_type` | Тип запуска |
| `started_at` | Время начала выполнения |
| `finished_at` | Время завершения выполнения |
| `status` | Статус выполнения |
| `error_message` | Сообщение об ошибке, если она возникла |
| `started_by` | Инициатор запуска |

Идентификатор `run_id` используется для связи запуска с загруженными наблюдениями.

### 5.2. Таблица `moex_raw`

Таблица содержит исходные данные бескупонной кривой доходности, полученные от MOEX.

| Поле | Назначение |
|---|---|
| `raw_id` | Идентификатор записи |
| `run_id` | Идентификатор запуска из `curve_run` |
| `tenor_years` | Срок до погашения в годах |
| `rate_pct` | Ставка доходности в процентах |
| `moex_tradetime` | Время торгового наблюдения |
| `loaded_at` | Время загрузки записи |

Особенности хранения данных:

- `run_id` ссылается на `curve_run.run_id`;
- при удалении соответствующего запуска связанные записи могут удаляться каскадно согласно внешнему ключу;
- сочетание `run_id` и `tenor_years` уникально;
- дата отчёта хранится в `curve_run.report_date`, поэтому отдельное поле `trade_date` в `moex_raw` не используется;
- `moex_tradetime` хранится как время, а `loaded_at` — как дата и время с часовым поясом.

### 5.3. Таблица `calendar`

Таблица содержит календарные признаки, используемые при проверке допустимости даты загрузки.

| Поле | Назначение |
|---|---|
| `calendar_date` | Дата |
| `is_working_day` | Признак рабочего дня |
| `is_trading_day` | Признак торгового дня |
| `note` | Комментарий |

Таблицы создаются средствами инфраструктуры проекта и не должны создаваться загрузчиком самостоятельно.

## 6. Настройка окружения

### 6.1. Создание виртуального окружения

Из корня репозитория выполните:

```bash
python -m venv .venv
source .venv/bin/activate
```

### 6.2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 6.3. Настройка переменных окружения

Создайте локальный файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Пример параметров подключения:

```dotenv
# Параметры PostgreSQL
DB_HOST=localhost
DB_PORT=5432
DB_NAME=irrbb
DB_USER=loader_rw
LOADER_PASSWORD=your_loader_password

# Альтернативный способ указать подключение
DATABASE_URL=

# Инициатор запуска
STARTED_BY=manual
```

Замените `your_loader_password` на пароль пользователя `loader_rw`, настроенный для вашей среды.

Если задана непустая переменная `DATABASE_URL`, она используется как строка подключения к БД. Если она пустая, подключение формируется из `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` и `LOADER_PASSWORD`.

Не добавляйте реальные пароли и другие секреты в Git. Файл `.env` должен оставаться локальным.

## 7. Требования к базе данных

Загрузчик подключается к существующей базе PostgreSQL проекта.

Для подключения используется пользователь `loader_rw`, предназначенный для выполнения операций загрузки. Его права должны соответствовать необходимым операциям чтения и записи в существующие таблицы.

**Загрузчик не создаёт и не изменяет структуру таблиц при запуске.**

Создание таблиц и управление схемой выполняются инфраструктурой проекта. В частности, загрузчик не должен вызывать `Base.metadata.create_all()` или отдельную функцию инициализации схемы для рабочей базы данных.

Перед запуском необходимо убедиться, что:

- PostgreSQL доступен;
- база `irrbb` существует;
- необходимые таблицы созданы;
- пользователь `loader_rw` имеет требуемые права;
- переменные окружения настроены правильно.

## 8. Запуск загрузчика

Запуск выполняется из корня репозитория при активированном виртуальном окружении.

```bash
python main.py
```

При необходимости можно задать инициатора запуска через переменную окружения:

```bash
STARTED_BY=manual python main.py
```

В качестве инициатора может указываться, например, `manual` для ручного запуска или `scheduler` для запуска планировщиком.

Фактическое поведение при запуске определяется текущей реализацией `main.py` и параметрами конфигурации.

## 9. Тестирование

Для запуска всех тестов выполните из корня репозитория:

```bash
python -m pytest -q
```

Для запуска отдельных наборов тестов:

```bash
python -m pytest tests/test_database.py -v
python -m pytest tests/test_loader.py -v
python -m pytest tests/test_moex_client.py -v
```

Тесты разделены по основным компонентам: работе с базой данных, логике загрузчика и клиенту MOEX.

Тестирование не требует использовать рабочую базу данных, если соответствующие тесты настроены на изолированную тестовую среду.

## 10. Обработка ошибок

При выполнении загрузки могут возникать ошибки, связанные с доступностью источника данных, обработкой ответа MOEX, проверкой даты или взаимодействием с PostgreSQL.

Информация о запуске хранится в `curve_run`. Поле `status` отражает результат выполнения, а `error_message` предназначено для сохранения сведений об ошибке.

Такой подход позволяет связать ошибку с конкретным запуском и упростить диагностику проблем.

## 11. Ограничения и особенности

- Загрузчик использует общую схему базы данных проекта.
- Структура таблиц должна быть подготовлена до запуска загрузчика.
- Пользователь БД, используемый загрузчиком, не должен получать права на создание таблиц только ради выполнения загрузки.
- Дата отчёта хранится в `curve_run.report_date`.
- Уникальность `(run_id, tenor_years)` ограничивает повторную запись одного срока в рамках одного запуска.
- Реальная доступность данных MOEX и корректность подключения к PostgreSQL зависят от конфигурации среды выполнения.

## 12. Результат работы

В результате выполнения загрузчика данные MOEX сохраняются в `moex_raw`, а информация о выполнении — в `curve_run`.

Сохранённые исходные наблюдения могут использоваться последующими модулями проекта для дальнейшей обработки и построения кривой доходности.

Модуль обеспечивает отдельный этап получения исходных рыночных данных и интегрируется в общую инфраструктуру проекта «Эконом Капитал. Модуль кривых».
